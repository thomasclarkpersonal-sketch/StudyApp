# A17 · Business Rules

Owner: Systems Analyst. Stage 2, written 2026-10-21. Catalog entry: A17. Approved and baselined at CP2 (2026-10-21).

This document records the 45 atomic, testable business rules (`BR-001`–`BR-045`) of the **Study App & Generation Pipeline**.
- **Rule types (`A17`):** `domain constraint`, `derivation`, `triggering operation`, `authorization`.
- Every `triggering operation` rule also specifies its five required parts (`user rule`, `event`, `entity name`, `condition`, `action`) in §3 (`A17`).
- Every rule traces to at least one use case (`A13`), conceptual entity (`A16`), or decision table (`A15`) (`G2.8`). Enforcement locations in code/DDL are assigned in Stage 3 `A31` so `A17` remains unchanged after `CP2`.

## 3. Five-part decomposition of triggering operation rules (`A17`)

Catalog entry `A17` requires every `triggering operation` rule to state its five parts (`user rule`, `event`, `entity name`, `condition`, `action`):

| Rule ID | 1. User rule | 2. Event | 3. Entity name | 4. Condition | 5. Action |
| :-- | :-- | :-- | :-- | :-- | :-- |
| `BR-011` | Never guess when a slide is unclear; flag it for human review. | Card or Question Creator encounters a source passage during Stage A or Stage B. | `FlaggedItem` (and `Card` / `Question`) | Source text/slide is illegible, uses an undefined symbol, or contradicts another slide. | Create `FlaggedItem` (`reason = "unclear_source"`, `disposition = "pending"`) and skip creating a `Card` or `Question` for that point. |
| `BR-014` | Items that still fail after 2 revision rounds (3 review rounds) go to `flagged.json`. | Reviewer completes round `r = 3` evaluation of a draft item. | `FlaggedItem` (and `ReviewRecord`) | `ReviewRecord.round == 3` and `ReviewRecord.verdict != "accept"`. | Create `FlaggedItem` (`reason = "failed_3_rounds"`), attach reviewer notes, and exclude the item from `*.final.json`. |
| `BR-022` | Re-importing a lecture suspends removed items instead of deleting them. | Student confirms a module re-import (`UC-06`). | `Card`, `Question`, `ImportBatch` | Item exists in the database for a lecture in `ImportBatch.lecture_ids` but its `id` is absent from the incoming file. | Set `suspended = true` on the `Card` or `Question` while keeping its `CardState`/`ConceptState` and review/attempt logs intact, and increment `ImportBatch.suspended_count`. |
| `BR-024` | Validate imports and back up the database before writing changes. | Student initiates and confirms a module import (`UC-06`). | `ImportBatch` (and SQLite database) | All uploaded JSON files pass `A34` JSON Schema validation and student confirms the diff preview. | Write a verified backup snapshot of the SQLite database file before starting the atomic import transaction. |
| `BR-027` | Every flashcard rating updates FSRS state and appends a review log row with prior state. | Student submits a flashcard rating (`1`–`4`) in `UC-07`. | `CardState`, `CardReviewLog` | Active `Card` is presented and `rating` is in `{1, 2, 3, 4}`. | Capture `state_before = CardState.state`, compute new `CardState` via `ts-fsrs`, update `CardState`, and insert a `CardReviewLog` row. |
| `BR-030` | When a concept runs out of unseen question variants, reuse the oldest and request a top-up. | Quiz scheduler selects a question variant for a due `Concept` (`UC-08`). | `Concept`, `FeedbackItem` | Count of never-seen non-flagged, non-suspended `Question` variants for `Concept.id` equals `0`. | Select the least-recently-seen available variant (or skip if `0` exist) and insert a `FeedbackItem` (`kind = "topup"`, `item_type = "concept"`, `item_id = Concept.id`, `exported = false`) if not already pending. |
| `BR-032` | Failing a concept quiz (`Again`) offers immediate review of the concept's flashcards. | Student completes a `QuestionAttempt` (`UC-08` or `UC-12`). | `QuestionAttempt`, `ConceptState`, `Card` | Mapped or overridden `QuestionAttempt.rating == 1` (`Again`). | Update `ConceptState` via `ts-fsrs` with `Again` (`1`) and prompt the student with the flashcards in `Concept.card_ids`. |
| `BR-036` | Defer optional items when today's plan exceeds the daily study time budget. | System generates or recalculates today's `DailyPlan` (`UC-10`, `UC-16`). | `DailyPlan`, `DailyPlanItem` | `sum(DailyPlanItem.est_minutes) > Settings.daily_budget_min` and at least one `DailyPlanItem` has `priority == "optional"`. | Defer `optional` `DailyPlanItem` rows in reverse priority order to subsequent days until total `est_minutes <= Settings.daily_budget_min` or zero `optional` items remain. |
| `BR-038` | Reporting a bad card or question flags it immediately and queues it for pipeline re-review. | Student submits a report (`wrong` or `unclear`) on a card or question (`UC-11`). | `FeedbackItem`, `Card`, `Question` | `reason` is in `{"wrong", "unclear"}`. | Insert `FeedbackItem` (`kind = "reported"`, `reason`, `comment`, `exported = false`) and set `flagged = true` on the `Card` or `Question`. |
| `BR-041` | Log tokens and USD cost on every Claude API call and enforce the monthly spend cap. | Study app dispatches or completes a Claude marking (`UC-12`) or tutor (`UC-13`) API call. | `GradingCallLog`, `TutorMessage`, `Settings` | `Settings.monthly_spend_cap_usd` is configured (`> 0`). | Compute `cost_usd` from `input_tokens`, `output_tokens`, and `Settings.token_rates_json`; if cumulative monthly spend `>= monthly_spend_cap_usd`, warn or block the call and fall back to self-marking for quizzes. |
| `BR-042` | Accepted tutor proposals go straight to a fresh Reviewer in the pipeline. | Pipeline processes `feedback.json → proposed` (`UC-14`, `UC-19`). | `Proposal`, `FeedbackItem`, `ReviewRecord` | `FeedbackItem.kind == "proposed"`. | Invoke a fresh Card or Question Reviewer subagent directly on `payload_json`; invoke the Creator subagent only if `ReviewRecord.verdict == "revise"`. |
| `BR-043` | Activate assessment mode when an exam or midterm is within 21 days. | Daily plan or quiz queue is computed (`UC-10`, `UC-15`). | `Module`, `Deadline`, `ConceptState` | Module has an unsubmitted `Deadline` with `type` in `{"exam", "midterm"}` and `0 < (due_at - now()) <= Settings.assessment_mode_days`. | Activate assessment mode for `Module`: prioritize concepts in `Deadline.covers_lectures` ordered by ascending `ConceptState.stability`, raise daily new-card limit for in-scope lectures, and add `assessment_prep` to `DailyPlan`. |
